# ADR 0004 — Contrôle de lisibilité ATS : extracteurs et interprétation des critères

- **Date** : 05/10/2026
- **Statut** : accepté
- **Contexte** : §12.2, §12.3 ; le cahier laisse quelques détails d'algorithme ouverts.

## Extracteurs

- **pdf.js** (via unpdf) : `getTextContent({ disableNormalization: true })`, lignes reconstruites avec `hasEOL`.
- **pdftotext -raw -enc UTF-8** de **Poppler**, cherché dans `POPPLER_BIN` puis dans le `PATH`. La sortie de `pdftotext -v` doit mentionner Poppler.
- Constat sur ce poste : Poppler est absent ; Git for Windows fournit un `pdftotext` **xpdf 4.00** (`C:\Program Files\Git\mingw64\bin`), visible dans le `PATH` de Git Bash. Il est **refusé** (`not-poppler`), car le cahier exige Poppler. Un essai ponctuel montre que son extraction des fixtures est propre et que le code de l'extracteur fonctionne.
- `npm run test:ats` échoue sans Poppler et affiche la procédure d'installation, sauf avec `ATS_SINGLE_EXTRACTOR=1` : le rapport est alors marqué « incomplet ». Dans l'interface et le MCP, l'absence de Poppler ne bloque pas l'export ; le rapport indique `complete: false`.

## Interprétations (le cahier est muet ou ambigu)

| Critère             | Choix                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-ATS-02            | Chaque texte attendu (champ par champ) doit se trouver, après `canon`, dans **chaque** extraction disponible                                                                                                                                                                                                                                                              |
| T-ATS-03            | Les « paires de mots consécutifs attendus » sont prises **à l'intérieur de chaque champ attendu**. Une paire est valide si `mot1\s+mot2` apparaît dans l'extraction brute. Un mot composé (`-`, `–`, `/`) coupé en fin de ligne compte comme anomalie. Orange si > 0, rouge si ≥ 1 % des paires                                                                           |
| T-ATS-04            | Liste ATS-06, **plus U+0000 et les caractères de contrôle C0** (sauf tabulation et fins de ligne) : un glyphe absent de la police est extrait comme U+0000 (ADR 0002)                                                                                                                                                                                                     |
| T-ATS-06            | Lignes non vides ; une ligne « est un intitulé » si elle est égale (au sens de `canon`) à l'un des intitulés de `projection.headings`                                                                                                                                                                                                                                     |
| T-ATS-07            | La plage est cherchée sur la ligne qui contient le début de l'intitulé (3 premiers mots) ou sur la suivante, en avançant entrée par entrée. « Aucune date dans un autre format » s'applique aux **plages des entrées** (contrôlées contre le motif du `dateStyle`), et non au texte des puces : la fixture `pieges` contient volontairement « 2019 - 2021 » dans une puce |
| T-ATS-08            | Zone « avant le premier intitulé » = lignes qui précèdent la première ligne égale à un intitulé. Téléphone comparé sur les chiffres. Le message orange donne seulement le nombre d'autres coordonnées, jamais leur valeur                                                                                                                                                 |
| T-ATS-09            | Les polices embarquées doivent appartenir à l'ensemble des noms PostScript du thème ; elles ne sont pas toutes obligatoires (Carlito-BoldItalic n'est pas utilisée)                                                                                                                                                                                                       |
| T-ATS-10            | Taille = `Math.hypot(t[2], t[3])` ; « corps » = taille la plus fréquente, pondérée par le nombre de caractères                                                                                                                                                                                                                                                            |
| T-ATS-13            | « Sans objet » dans le MCP et les tests (rendu déterministe, vérifié par un test de SHA-256) ; contrôle à l'export dans l'interface au lot 3                                                                                                                                                                                                                              |
| T-ATS-17            | Analyse statique exécutée aussi dans chaque rapport (coût nul, résultat mis en cache)                                                                                                                                                                                                                                                                                     |
| T-DOCX-03           | LibreOffice absent : orange permanent « 1 page non garantie en DOCX »                                                                                                                                                                                                                                                                                                     |
| Débordement         | Si le PDF A4 a plus d'une page, les critères autres que T-ATS-01 sont calculés sur le PDF de mesure (`height: auto`), comme le prévoit le §12.2                                                                                                                                                                                                                           |
| Dépassement chiffré | `ceil((hauteur du contenu − hauteur utile) / pas de ligne)`, avec pas = (hauteur de capitale de Carlito + interligne) × taille du corps                                                                                                                                                                                                                                   |

## Proposition de correction du cahier

Ajouter à T-ATS-04 : « … ainsi que U+0000 et les caractères de contrôle C0 (un glyphe absent de la police est extrait comme U+0000) ». Préciser dans T-ATS-07 : « aucune plage d'entrée dans un autre format ».
